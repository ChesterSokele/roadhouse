# Roadhouse Deli & Grill — website

Static multi-page site (HTML + CSS + vanilla JS) built with Vite. No framework.

```bash
npm install
npm run dev       # local dev server (http://localhost:5173)
npm run build     # optimises images and writes the finished site into the project root (index.html, assets/, img/ …)
npm run preview   # serve the built site locally (http://localhost:4173)
```

## Where things live

| What | Where |
|---|---|
| **Menu items, prices, descriptions** | `src/data/menu.json` — edit, then rebuild. `menu.html` is generated from it. |
| Page markup | `index.html`, `menu.html`, `booking.html` (shared header/footer: `src/partials/`) |
| Design tokens (colours, type, spacing) | `src/css/tokens.css` |
| Components / pages CSS | `src/css/*.css` |
| Behaviour | `src/js/` (`common.js` nav + language, `home.js`, `menu-page.js`, `booking.js`) |
| Languages | `src/js/translations.js` (English is the page markup itself) |
| Admin (staff portal) | `admin.html` — unchanged; manages meals, events, specials, notices, reviews in Firebase |
| Original photos | `images/` (+ `atm.png`, `straw.jpg`, `logo.png`). Never served directly. |

### Menu data format
Each section in `menu.json` has `groups`. A `dishes` group lists `{ name, desc, price }` (or `prices: [{label, price}]` for sizes,
`virgin` for a non-alcoholic price, `tag` for a small label such as "Best Seller", `image` for a thumbnail name from `scripts/optimize-images.mjs`).
A `drinks` group is a table: `columns` (e.g. `["Tot","Bottle"]`) and `rows` of `{ name, prices: [...] }` (`null` = not offered).

### Adding / changing photos
Add the file to the `photos` list in `scripts/optimize-images.mjs`, run `npm run images`, then reference it with
`<rh-img name="your-name" alt="…" sizes="…" />` in HTML or `"image": "your-name"` on a menu item (thumbnail).
The script writes AVIF + WebP at several widths and `src/data/images.json` (used to set width/height and avoid layout shift).

## Deploying
Deploy the project root as built (index.html, menu.html, booking.html, admin.html, assets/, img/, plus the logo/favicon/pdf/robots/sitemap files). Editable sources live in `pages/` and `src/`; always run `npm run build` after editing them. Recommended server settings: gzip/brotli for html/css/js/svg, and
`Cache-Control: public, max-age=31536000, immutable` for `/assets/*` and `/img/*` (file names are hashed / versioned by rebuild);
short cache for the `.html` files.


## Languages & theme
- **Theme** follows the visitor's device (`prefers-color-scheme`). Colours live in `src/css/tokens.css` (dark default + a light override).
- **Languages** (EN, AF, PT, DE, FR, IT, ZH, HI, JA): English is the page itself. The build tags every text string automatically;
  translations are rows `[english, af, pt, de, fr, it, zh, hi, ja]` in `src/i18n/strings-*.js` (the English text is the key).
  When you add or change English text (in a page or `menu.json`), add/update its row, then `npm run build`.
  A string with no row simply stays in English — that is how brand names (Jameson, Wagon Wheel Burger…) are kept as printed.
- Text typed into `admin.html` (events, specials, notices, meals) and guest reviews are shown exactly as written; only the labels around them are translated.
- The WhatsApp booking message to the restaurant is always English so staff can read it.

## Menu structure
`menu.html` is the hub (today's meal + one image card per category). Each category has its own page, `menu-<id>.html`
(burgers, grills, pizza, wraps, platters, cocktails, drinks, wines, softdrinks), generated by `scripts/make-menu-pages.mjs`
from `src/data/menu.json` — so `npm run build` is all you need after editing the menu. Each category page has a sticky
switcher (jump to any other category), previous/next links and image cards for the rest of the menu.
The card photo and teaser line for a category are the `card` entry of that section in `menu.json`.
`pages/menu-*.html` are generated files; don't edit them by hand.

## Dish photos
Food and cocktail pages show a square photo beside every dish; spirits, beers, wines and soft drinks stay text tables.
Put photos in `photos/menu/` named exactly as listed in `photos/menu/CHECKLIST.md` (e.g. `rump-steak.jpg`), run `npm run build`,
and each one is cropped, compressed (AVIF/WebP) and attached automatically. The checklist updates itself (✅ / ⬜).
Dishes without a photo show a neutral tile with the logo. Photos in that folder override older ones set in `menu.json`.
